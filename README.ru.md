## Что это

Mihomo Launcher рассчитан на нетехнического пользователя: вы один раз настраиваете, *какие программы и сайты ходят через VPN и через какие узлы*, а пользователь просто жмёт **Подключиться**. Лаунчер поднимает туннели, проверяет доступ и открывает программы.

## Ключевые возможности

- **Правило = приложение + диапазоны IP/доменов.** Главная фишка. В одном правиле и само приложение (или сайт), и его диапазоны адресов — добавьте готовый шаблон сервиса, и **весь** его трафик пойдёт в один туннель. Реальный IP не утечёт «мимо» правила.
- **Готовые шаблоны диапазонов.** Целые наборы доменных/IP-правил из открытого репозитория [blackmatrix7 / ios_rule_script](https://github.com/blackmatrix7/ios_rule_script) — тысячи сервисов, поиск по названию, автообновление.
- **Свой туннель у каждого правила.** Несколько узлов работают одновременно: одно приложение — через Францию, другое — через Германию, третье — напрямую. mihomo (Clash.Meta) держит несколько userspace-WireGuard туннелей сразу, без лимита «один туннель».
- **Вся схема одной таблицей.** Кнопка **Routing** на главном экране открывает таблицу: строки — правила, столбцы — ваши VPN-варианты. Клик по клетке ставит номер: 1 — первый вариант, 2 — запасной, и так далее; пустая клетка — этот VPN правилу не достаётся. Отдельная колонка — kill-switch.
- **Разные типы VPN-источников.** WireGuard `.conf`, `vless://` (VLESS / Reality), `hysteria2://`, Clash/mihomo-подписки.
- **Kill-switch в два слоя.** На каждом правиле. Пока туннель не поднят, у правила нет интернета — трафик отклоняется движком, а не идёт напрямую. Ту же блокировку дублируют правила брандмауэра Windows, поэтому она держится, даже если движок упал, перезапускается или лаунчер закрыт. Локальную сеть, принтеры и удалённый стол защита не трогает.
- **Не отрежет удалённый стол.** Адреса активной RDP-сессии лаунчер находит сам и держит вне туннеля и вне блокировок. Сверху — режим «Remote desktop session»: пока включён, движок гасится каждые 60 секунд, так что даже безнадёжный конфиг вернёт доступ за минуту.
- **Проверка соединения по отклику сайта.** Доступность определяется по телу ответа (блок-маркеры), а не по коду статуса — Cloudflare-403 не путается с реальной блокировкой. Лаунчер перебирает десятки узлов и повторяет попытки сам, примерно раз в 90 секунд, пока сервис не откроется.
- **Приложения из Microsoft Store** (ChatGPT, Claude, …) через стабильный AUMID, плюс обычные `.exe` и сайты.
- **Геолокация сервера на каждой плитке** (страна, город) по локальной базе MaxMind GeoLite2 — полностью офлайн.
- **Живой лог «Что заблокировано и почему».** Каждое соединение с вердиктом: сработало правило, отрезал kill-switch, вырезал рекламу/трекер DNS-сервер вашего компьютера или программа ходила напрямую мимо утилиты. Вкладки: «Проблемы», «Реклама и трекеры», «Мимо утилиты», «Всё подряд».
- **Двуязычный интерфейс (RU / EN)**, переключение на лету.
- **Встроенное онлайн-обновление по пунктам**: лаунчер, движок mihomo, база геолокации и списки диапазонов показывают версию и дату, у каждого свой период проверки, любое можно обновить принудительно на вкладке «Обновление».

## Как это работает

Каждое правило объединяет цель (приложение, сайт или Store-приложение по AUMID) и её диапазоны доменов/IP. При нажатии **Подключиться** лаунчер для каждого VPN-узла по очереди собирает конфиг: уже закреплённые правила остаются на своих узлах, а остальные (и сам лаунчер) пробуют текущий. Доступность проверяется по телу ответа, рабочий узел закрепляется, остальные едут дальше — так перебираются десятки узлов, пока всё не откроется. Что не подошло ни под один узел — остаётся под kill-switch (отклоняется), а не идёт напрямую; ту же блокировку держат правила брандмауэра Windows, пока движка нет. Геолокация сервера — по локальным базам MaxMind, без обращений в облако.

## Требования

- Windows 10 или 11 (x64)
- .NET Framework 4.8 (есть в Windows; ставится автоматически, если отсутствует)
- Свои VPN-узлы (WireGuard `.conf`, ссылка `vless://` или `hysteria2://`, Clash/mihomo-подписка)

## Вопросы

**Не утекает ли реальный IP?** Нет. Правило отправляет *весь* сервис (приложение + его диапазоны) в один туннель, а kill-switch блокирует правило, когда туннель не поднят.

**Что будет, если движок упадёт?** Правила брандмауэра Windows остаются на месте: программы из правил с kill-switch не выйдут в интернет мимо туннеля, даже если лаунчер закрыт. Сам движок лаунчер сторожит и поднимает заново, восстанавливая маршруты.

**Сайт не открывается — как понять почему?** Откройте окно живого лога: по каждому соединению виден вердикт, сразу ясно, виновато правило, kill-switch, ваш DNS (реклама/трекеры) или сама программа.

**Какой движок?** [mihomo](https://github.com/MetaCubeX/mihomo) (Clash.Meta) — WireGuard, VLESS/Reality, Hysteria2, TUN, маршрутизация по процессу и домену. Несколько туннелей одновременно.

**Бесплатно? Телеметрия?** Бесплатно, без телеметрии. Геолокация — локальная база MaxMind GeoLite2; конфиг хранится на вашей машине. В интернет лаунчер ходит только за обновлениями (с вашего подтверждения) и за списками правил.
